# Milestone 6: Gamified market — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task lives in its own step file.

**Goal:** The market becomes the place the player learns to *choose* food (spec §3.5). Four stall keepers (Old Wen, Big Bram or his Protein Counter, Okafor-Sato and the Spice Merchant) each run short multiple-choice minigames from the 137 KB of stall content M4 Step 12B left out of the bundle. The rounds are: Wen's "Seasonal or well-travelled?" for the player's own region and month, ripeness and storage; Bram's cut match, chalkboard cost-per-serving, label and safety quizzes; Okafor-Sato's tofu match and legume lore; and the Spice Merchant's blind-sniff, freshness and substitution riddles. They run in practice mode any day, and they never stand between the player and the shopping list. Every question is checked by the rules engine before it is shown, so a blocked or unverifiable item is never a correct answer. Correct choices earn a little XP and a stall stamp. A wrong answer earns a funny, true explanation and costs nothing. Market day gets richer too:
- **Amounts:** Form 12-M shows how much of each item the plan needs.
- **Stall swaps:** an item that's out of stock gets a stall keeper's labelled substitute, re-checked against the player's rules.
- **The Season's Table:** an honest "in season where you are" note on produce, from a curated table for the player's own region. A region with no table gets no guessed one.
- **Spoken check-off:** the Pan's `check_off_item` ("got the shallots, they were out of curry leaves"), with a card the player taps.
- **Errands:** a quest errand now plays the stall's own question for its item.

The milestone also closes four M5 carries: the server progress snapshot (m12), restriction-verb tuning in plan requests (N2), the ROADMAP id test (N3), and the drill-first hint, which waits on a founder decision.

**Architecture:** Everything that decides lives in `packages/core`, so the device and the server compute the same thing:
- `market/` (new): stall banks, rules filtering, the Protein Counter variant, answer scoring, the seasonal table and region resolution, and the stall-file validator;
- `week/`: market-list amounts and out-of-stock stall swaps;
- `progress/`: the `stall_round` event, its grants and the snapshot checkpoint;
- `mentor/`: the check-off grammar and card (Step 8 only, because these files are eval-hashed).

Stall content ships as its own lazy chunk (`virtual:kq-market`), loaded only by the market screens, so first paint stays under budget. The API gets:
- the stall banks and the seasonal table in its boot catalogue, validated by the same core checks;
- a sealed body for health-revealing progress events (a Protein Counter round reveals a meat-excluding rule);
- a sealed `progress_snapshots` table, in export and delete, invalidated by a database trigger whenever an event is erased;
- a stock route on market runs;
- one new write card, `check_off`, which the model can only propose through `propose_check_off`, with verbatim item names that code matches to the open run.

Signed out, everything except the account-only rows works on the device. With the AI off, everything works except the model's check-off proposal, which the scripted grammar covers.

**Tech Stack:** Node 22, Fastify 5.12, drizzle 0.45, Postgres 16, zod 4, `yaml`, Vitest 5, Vite 8, Phaser (already lazy), and Playwright 1.63.0 (pre-installed Chromium). No new runtime dependencies.

## Global Constraints

Quoted from the spec unless marked. Every task's requirements include this section and the M2–M5 Global Constraints (`plans/m2-api/README.md`, `plans/m3-game/README.md`, `plans/m4-mentor/README.md`, `plans/m5-loop/README.md`).

- §2.1: "The AI suggests, deterministic code decides." (Plan rule: the model never picks a question, an answer, a swap, a season or a list row. `propose_check_off` carries only the player's verbatim item words. Core `matchCheckOff` maps them to open run rows, or nothing. Correctness is decided by core `scoreAnswer` against the stall file, never by the client's or the model's claim.)
- §2.2: "'Can't verify' is never 'safe.'" (Plan rule: every stall question, every option a question offers as correct, every item tip, every stall swap and every Season's Table note runs through core `check` with the player's active rules on the local date. A question is dropped when anything it names is ⛔ or ❓. A question names an item itself, not a recipe line the engine could swap, so it is checked with no substitutions: a named item the rules hit is ⛔, never 🔁 (lard under "no pork", garlic under low-FODMAP, soy sauce under a soy rule are dropped even though `data/substitutions.json` has swaps for them). That covers its declared `contains`, plus every ingredient the graph can find in its prompt, options and explanation (`textMentions`, as M5's `noteMentions`). A swap is offered only when every dish it serves checks ✅ or 🔁 with it. An unknown `contains` id fails the build; it is never treated as "no ingredient".)
- §3.5: "The minigames run in practice mode any day. They are optional on market day: they earn XP but never gate the shopping list." · "Blocked items never appear as correct answers." · "Wrong answers get a funny explanation from the stall NPC, never a penalty." (Plan rule: no market-list, tick, finish, swap or quest path waits on a minigame. An errand's question passes the step whatever is answered.)
- **No pressure mechanics (milestone rule, from §16 never rules 4, 5 and 8, and the audit).** Minigames have no timer or countdown, no lives, no streak or "in a row", no combo or multiplier, no score tally ("4/5", "x of y"), no leaderboard, and no random or mystery reward. Question order is deterministic (see Ruling 7). The same rewards come on every day of the week; market day gives no bonus. Every round can be left at any question, and leaving costs nothing. The architecture grep from M5 Step 12 (`no-streak.test.ts`) extends to core `market/`.
- §16 never rule 5: "No paid urgency; scarcity only mirrors real seasons." (Plan rule: The Season's Table is information only. It never hides, locks or reorders a dish. No season copy counts down ("only two weeks left"), and out of season is "well-travelled", never wrong (voice §5).)
- §16 never rule 7 and **prices** (milestone rule): "Mentors and cooks never sell." No stall keeper sells anything in-app: there is no buy button, no checkout, no affiliate link and no product brand. Chalkboard prices are **example numbers in no particular currency** (Ruling 5). They are never real, never regional and never a claim about any shop. The market list shows no prices.
- **Regionally honest seasonality (milestone rule).** There is no default region, no default hemisphere and no fallback to another country's calendar (Wen's file header suggests `pnw-usa → us-north`; Ruling 9 allows only a declared same-country parent that is itself in the table). Core `seasonRegionFor` matches the player's own profile country and region against the curated table. No match, or more than one, gives `null`: then the seasonal round and the Season's Table notes are left out, and a plain line says so (`market.no_calendar`). Each region declares its own categories (a monsoon or dry-season region doesn't get "stored from the autumn harvest"), its sources and a `# REVIEW:` status. Month comes from the player's local date. The region never reaches a prompt (C-13).
- **Decolonial and respectful framing (voice §0, §5).** No "exotic", "ethnic", "authentic", "weird", "strange" or "unusual" about food. Nothing is "smuggled" (Ruling 6), a spice is never "mysterious", and no cuisine's food is a "version of" another's. Labels and agency figures from one country carry a `countries:` scope and are shown to players in that country only (Ruling 8). Okafor-Sato is never gendered. Bram never moralises meat. The Protein Counter is a full stall, not a lesser one.
- §7.0: "`check_off_item` | Market run check-off | None (undoable)", and "Every write shows as a small card in the conversation." (Plan rule: a spoken check-off becomes a `check_off` card. One tap ticks every matched row; unticking any row is the undo. Nothing ticks without the tap. A stall swap is a tap on the swap chip.)
- §7.6b (binding, unchanged): the server guards every write. Read-backs come from code. The card is the record. Page events never arrive as user text. The output filter applies. M4 Ruling R9 stands: the model's free text is never shown. Stall keepers have **no AI in M6**: their lines are written only (M5 Ruling 21 carries), their FAQ is tappable written questions with written answers, and there is no free-text box at a stall.
- **Any AI use goes through the M4 eval gate (C28).** Step 8 changes the Pan's tools and decision code, so `evalHash` changes and `apps/api/test/eval-gate.test.ts` fails until a passing `apps/api/eval/last-pass.json` is recorded. Step 8 makes **one** `npm run eval:mentor` run by the implementer, with no re-roll. Never set `MENTOR_EVAL_GATE=skip-no-network`, on any branch (controller ruling, overriding Ruling 22).
- §6: "Nothing earned is taken back." (Plan rule: a stall round's grants are fixed when made. A wrong answer, a dropped question, a rules change, a `health_data` delete erasing a Protein Counter round, a snapshot rebuild and a `rewards.yaml` retune lower nothing. Snapshots are a cache: rebuilding one may never change a derived value, and a property test pins it.)
- §10: no stall question, tip or Season's Table note names a `sacred: true` dish. A sacred dish adds nothing to the market list (M5) and so gets no amounts and no swaps.
- §19 and M5 Ruling 25 (C31): **Family Table** may play stall rounds in practice by tapping. It shows scripted lines only, with no text box and no FAQ text, and it records nothing (no `stall_round` event, no tick, no swap, no check-off card, no stamp). Children never reach the model: the check-off grammar and the model path are both behind the M4 child guards. No purchase prompt, price or Guild appears in any child-facing view; Bram's chalkboard numbers are teaching numbers, footnoted, and the never-rules scan covers Family Table mode.
- §9, §20, standing compliance rule: GDPR Art. 9, FTC HBNR and WA MHMDA are covered as we go. Every new column has a `data-inventory.md` row and §6 columns (N-8 test), export (decrypted) and account delete. A health-revealing event body is sealed per row and erased on a `health_data` withdraw-with-delete. We never claim HIPAA: the words "HIPAA" and "medical-grade" appear in no copy (M4 Step 12 scan, extended to the stall files).
- C-13: prompts carry no identifiers, no dates, no region, no market list and no stall answers. The check-off tool gets no list: code matches. P-5: no item, stall question or region in a URL.
- **First paint ≤ 400 KB (348.0 KB at M5's end).** The stall content, the minigame panel, the market scene and the check-off card are lazy chunks. First paint may grow by at most 4 KB (route entries and the kitchen's market link): **≤ 352 KB**, asserted by `budget-plugin.test.ts` and the build. The service worker precaches the lazy chunks (`sw-plugin.ts` already precaches every bundle file), so practice mode works offline.
- Error body shape is M2's. New codes: `stock_invalid` (400, a swap the core didn't offer, or a row that can't be marked out). Stall-round problems are per event in the 200 `rejected` list (`bad_event`, `consent_required`), as M5's C14. They are added to the doc comment on `ApiError` in `apps/api/src/errors.ts`.
- **One lock order, everywhere (extends M5's):** user row (`lockLiveUser`) → advisory `rules:` → `pantry:` → `plan:` → `progress:` → `book:` → consent row (`lockConsentIn`) → conversation row → data rows in table order `rules` → `meal_logs` → `margin_notes` → `messages` → `mentor_proposals`, then `meal_plans` → `market_runs` → `shared_table` → `progress_events` → `reward_grants` → `progress_snapshots`.
- **No market logic is written twice:** whatever the device and the API both decide (question filtering, scoring, the variant, rewards, amounts, swaps, season notes, check-off matching) lives in `packages/core` and is exported from both `index.ts` and the browser-safe `engine.ts`.
- Tests never touch the network. The model is the fake `AiProvider` (except the one eval run). API tests use real Postgres. Game e2e mocks `/api/**` with `page.route`.
- Constants (tunable, one place each, core `market/` unless noted): `ROUND_SIZE = 5`, `MAX_ROUND_ANSWERS = 10`, `SNAPSHOT_EVERY = 500` (core `progress/`), `MAX_STOCK_SWAPS_PER_RUN = 21` (core `week/`). Reward amounts live in `data/rewards.yaml` (`xp.market_game`, `stamps.market_game`). Seasonal regions live in `data/seasonality.yaml`.

## Review Focus

1. **A stall question, option, tip or swap shown as fine when the rules engine can't say so.** Examples:
   - a tofu question for a soy rule, while `tofu` isn't in the graph;
   - Bram's beef braise for a vegetarian;
   - a Protein Counter egg question for a vegan;
   - the Spice Merchant's asafoetida answer for a coeliac;
   - a "use tamari" substitution answer for a soy rule;
   - a seasonal round naming strawberries for a strawberry allergy;
   - "out of shallots, take onion" for an allium rule;
   - a Season's Table "in season" badge on a ❓ item.

   Each must be absent, or shown with ⛔ / ❓ and never as the correct or offered choice. → Steps 1, 3, 4, 5, 9, 10.
2. **Pressure, loss or loot.** A timer, a countdown, "3 in a row", a score tally, a lost life, a random reward, a market-day bonus, a season countdown, a stamp withheld for wrong answers, or a minigame gating the list, a tick or an errand. → Steps 1, 3, 9, 10, 11.
3. **Region dishonesty.** A player with no region, or in Kerala, Oaxaca, Lagos or Melbourne, shown the Pacific Northwest calendar; "stored from the autumn harvest" in a tropical region; a USDA label question for a UK player; an implied default hemisphere. → Steps 2, 4, 9.
4. **A write without a tap, or by the model.** `propose_check_off` carrying a name the player never said; an injected item name in a pasted recipe ticking a row; a check-off card in Family Table; a stall-round event forged to claim answers it never gave, or for a question the player's rules hide; a stock swap the core didn't offer. → Steps 3, 6, 8, 10.
5. **New personal data outside sealing, consent, export or delete.** A Protein Counter round (reveals a meat-excluding rule) in a plain column; the snapshot holding dish slugs unsealed; the snapshot outliving an erased meal-log event; the region in a prompt or a URL. → Steps 6, 7, 8, 11.
6. **Cultural framing.** "Smuggled", "exotic", "mysterious spice", a cuisine as a "version of" another, Okafor-Sato gendered, meat moralised, prices in one country's currency. → Steps 4, 5, 11.

## Rulings

Where the spec, the audit and the content disagree or are silent, the planner decided as follows. The form is `Ruling: <decision> — <why> — <cost if wrong>`. **[founder]** marks the ones the founder should confirm before the step that uses them is dispatched.

1. Ruling: **Stall rewards are 5 XP the first time each question is answered correctly (once per question id for the account's life), and one `market_game` stamp per stall per ISO week for any finished round, whatever the answers.** Nothing for a wrong answer; nothing is lost either. — §3.5 says correct choices earn XP and stamps. A lifetime once per question means practising earns nothing more but costs nothing, so there's no grind or farm. A stamp for *finishing* rather than for scoring keeps a wrong answer from costing anything, which would otherwise be "a penalty" by omission. The ISO week matches M5 Ruling 23 and isn't a streak (no consecutive weeks). — Amounts are data (`rewards.yaml`). If the founder wants the stamp tied to a correct answer, that is a one-line grant change. **[founder]**
2. Ruling: **Stall-round correctness is decided by core from the stall file.** The event carries `{ stall, answers: [{ q, pick }] }`: question ids and the option index in file order. It never carries a "correct" flag. — §2.1, and M5's "a client never says what it earned". — Re-ordering a question's options in the YAML changes what an old `pick` meant. The build therefore pins option order once a question ships: a changed option order needs a new question id (Step 5 test).
3. Ruling: **The Fishmonger and Dairy & eggs stalls (§3.5 rows 3 and 6) are not built in M6.** M6 ships the four written stalls. Fish and dairy stay at the General Counter (`data/stalls.json`, M5). — There is no content for them, and a stall needs a writer and a reviewer. Shipping an empty stall, or AI-written questions, breaks §8 "scripted first". — Two §3.5 skills (fish freshness, egg dates and cheese types) wait for M10 content. `STALL_IDS` then grows, which is data plus one union type. **[founder]**
4. Ruling: **The Protein Counter is used when the player's active rules block `meat` itself** (a check of the `meat` category is ⛔: vegetarian, vegan, or a custom rule covering all meat). A partial rule ("no pork") keeps Big Bram, with the pork and lard questions dropped. With rules that can't be read (`rules() === null`), the stall waits, as quests do (M5 fail-closed). — `content/README.md` ties the variant to "rules exclude meat", and a partial rule must not switch the whole stall. — A player who avoids beef and chicken but not pork sees Bram with only pork questions. This is correct, but sparse.
5. Ruling: **Chalkboard prices are example numbers in no particular currency.** No `$`, `£`, `€`, `₹` or `¢`; cent figures ("26¢") are written in the same unit as the price ("0.26"). Each value question that compares prices (two today: `bram-braise-value` and `bram-pc-cheapest`) gets a structured `chalkboard: [{ price, servings }]`, one entry per option in file order (the option's own text names it), and the build checks the arithmetic: the correct option has the lowest price per serving, and every number in the reactions matches. The other four `game: value` questions (protein per 100 g, bean yield, yogurt, peanut butter) compare no prices and carry no chalkboard. Form 14-S (stalls) carries the footnote "*Example prices in no particular currency. Your shop will differ." Form 12-M shows no prices, so its footnote drops "Example prices". — §16 never rule 7, "never real or regional claims", and the file's own `# REVIEW: localise prices per region`. Localising them would make them regional claims. A unitless number teaches the skill (divide by servings) everywhere. — The numbers read slightly abstract. Rewording the price questions back is content only. **[founder]**
6. Ruling: **"Seasonal or smuggled?" becomes "Seasonal or well-travelled?"** — "Smuggled" frames shipped food as a crime, against voice §5 ("out of season is 'well-travelled', not a crime") and the decolonial stance: much of the world's produce travels from the Global South. — The spec's §3.5 name changes. The founder may prefer another title, which is content only. **[founder]**
7. Ruling: **Question order is deterministic, and nothing in a round is random.** Core `nextRound` picks up to `ROUND_SIZE` questions. Unanswered-correctly questions come first, then by least recently answered, then by file order. **Options are shown in a fixed per-question order**: core `optionOrder(questionId, n)` is a permutation from a stable hash of the id, the same every time and on every device. `pick` is still the file index. Today the correct option is the first one written in 82 of the 93 questions (all of Bram's, Okafor-Sato's and the Spice Merchant's), so file order would give the answer away. — Never rule 4 (no randomness near a reward), testability, and the voice rule that rounds teach categories, not position. — Rounds can feel samey to a player who has answered everything. That is acceptable: practice earns nothing more anyway. A test pins that across each stall's bank no display position holds more than half the correct answers.

It is shown only when the player's profile country matches. With no country set, only unscoped questions are shown. The build fails on a question naming a listed agency (`USDA|FSIS|FDA|FSA|NHS|FSANZ|CFIA|EFSA|FSSAI`) without a scope. — Regionally honest: a UK shopper should not learn a US label as if it were theirs. — Bram's label round is thin outside the US until reviewers add other countries' labels (M10).
9. Ruling: **Seasonal data is a curated table, `data/seasonality.yaml`, with one entry per region.** Each entry has a display name, `status: draft | reviewed`, cited sources, match phrases for profile country and region, its own category set (e.g. `now`, `stored`, `travelled`), and per month the ingredient ids in each category. M6 ships **only `pnw-usa`**, built from the sources already cited in `wen.yaml` for November–February and `# REVIEW:`-flagged. The other months are left empty, which means no note, never a guess. Wen's seasonal questions must agree with the table (the build cross-checks them). There is no `fallback` to another country. Wen's existing `fallback: us-north` is kept only as a declared same-country parent, which must itself be in the table, and `us-north` is not written yet. — §3.5 says "a curated table by region and month", and regional honesty. One region exists today. Inventing Kerala, Oaxaca or Kansai calendars without a reviewer who shops there would be exactly the dishonesty this milestone must avoid. — At launch most players see `market.no_calendar` and no seasonal round until reviewers write their region. **[founder]**: which regions next, decided with the ROADMAP launch-region item.

Ruling: **The Season's Table is information, not a mechanic.** A list row or a plan dish whose produce is in the region's `now` category for this month gets a small "in season where you are" note (`season.now`). A seasonal tie-break in "pick N" can come later.
11. Ruling: **A stall swap comes only from the curated `data/substitutions.json`, never from the model.** Core `stockSwaps(row, plan, ctx)` offers a swap only when every dish in `row.forDishes` checks ✅ or 🔁 with it, on that dish's plan date (core `checkWithNotes`, with the swap applied as a note op). Taking it marks the row `outOfStock`, adds a ticked row for the swap labelled "stall swap for {dish}", and puts the swap in the pantry, dated. In cook mode the dish shows "swapped at the market: Y for X" and is checked with the swap, for that plan week only. No offerable swap → the stall's `out_of_stock_none` line and a plain "skip it this week". — §3.2 "the stall NPC offers a labeled substitute, re-checked by the rules engine", and §4.4 "curated table first, then AI suggestions" (the AI half is M8 with grounded Q&A). — Swaps are few until the table grows. Step 4 adds a reviewed handful for the launch dishes' market items.
12. Ruling: **Amounts on Form 12-M are summed only when the unit strings agree after core's unit normalisation** (`nutrition/units.ts` `unitFamily`, one table with `toGrams`; the families are mg/g/kg, oz/lb, ml/l and tsp/tbsp, and cup stands alone, singular and plural folded). Otherwise they are listed side by side ("2 tbsp + 1 cup"). Fuzzy amounts ("a handful", "to taste", a null quantity) are shown as written. Each dish's amount scales by plan servings ÷ recipe servings. Nothing is converted between volume and mass on the list. — "Can't verify is never safe" applied to arithmetic: a list must not invent a weight. — Lists can read "1 onion + 200 g onion". This is honest, if clumsy.
13. Ruling: **Spoken check-off has a closed grammar, and bare "no X" stays a health turn.** Core `checkOffIntent` consumes these forms:
    - "got / bought / picked up / grabbed <items>";
    - "they were out of <item>", "couldn't get <item>";
    - "no <item> today / left / in stock".

    Each `<item>` must match an open run row. Bare "no fennel" stays a restriction cue (M5 N7, "when in doubt, health") and gets the M4 health ask, not a check-off. Any severity, allergy or symptom word anywhere sends the message to the health path first (M5 I1). The whole-message rule holds: a code card is built only when every clause is consumed (M5 Ruling 5a). — The spec's own example "got the chicken thighs, no fennel" collides with "no X" as an allergy statement. Mistaking an allergy for a stock note is the worse failure. — A player who says "no fennel" gets a gentle ask before the tick: one extra turn. **[founder]**
14. Ruling: **The model may call only `propose_check_off { got: string[], missing: string[] }`.** Each string must be verbatim in the player's words and pass the filters (M5 Ruling C1 / R5). Core `matchCheckOff` maps the strings to open run rows. Unmatched strings are dropped and named in no reply. With no open run the tool does nothing, and the Pan offers a `go` chip to `#/market`. The prompt carries no list (C-13 minimisation). — §2.1, and the M5 lesson that model-supplied strings are attack surface. — The model can't fix a mis-said item name. The player taps the row instead.

Ruling: **The server progress snapshot (M5 m12) is a sealed cache, never a record.** It is `progress_snapshots(user_id pk, upto_seq, catalogue_hash, sealed)`, holding core's `ProgressSnapshot` of the fold up to `upto_seq` under the current catalogue and rewards hash.
